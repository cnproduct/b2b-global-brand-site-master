# 行业采购组件与 Agent 交互

沿用上游有用的采购组件思路，具体启用由行业、真实资料和访客任务决定；不以 Bento、某字体、三个悬浮按钮或 WebMCP 作为所有站的固定造型。

## 规格与选型

优先规格表、型号/材料/应用筛选、已验证差异对比、技术文件和定制范围。转换单位时保留原值、条件、舍入，计算器须写最小检查。规格表从同一批公共事实生成。移动端保留表头与横向滚动提示，不将小字技术参数塞入纯图片。

Good/Better/Best 是方案组织方法：比较实际可供应的材料、工艺、服务和适用条件，不为凑三级编出MOQ、交期、认证和虚假价格。没有三种实际方案就不显示三档。

## RFQ 和移动入口

基线生成器输出邮箱联系，可在用户已有服务或已授权后端上实现 RFQ。先准备明确的接收目标、必要字段、附件权限、隐私说明、服务器校验、限流/反垃圾以及成功/失败路径，再接公共表单。前端成功必须来自真实服务响应；最终收件/CRM记录另行验证。不自动发送测试询盘到未获准的第三方地址。

行业技术字段渐进展开；手机端操作不遮挡产品参数或键盘。WhatsApp必须使用实际官方号码；样品入口只有在真实提供该服务时展示；PDF按钮必须打开真实PDF，而非将Markdown标成PDF。客户成本、联系人、图纸保持权限隔离。

## 可选装柜容量估算

页面模型 estimator=true 时加入五个手动输入：数量（非负安全整数）、每件含包装容积m³、每件毛重kg、可用容积m³、允许载重kg。没有默认SKU包规和统一“20GP/40HQ”额定值；按船公司、箱型、路线与实际装载约束提供输入。

容积利用率=总容积/可用容积；重量利用率=总重/允许载重；容量下界柜数=ceil(max(两种比值))。利用率不截断到100%，超载应可见。几何堆码、托盘、重心、门尺寸、混装、线路重量限制和运费均不在此模型中；需要这些时换专业装箱或运价系统，不把结果改名“精确到岸价”。

## 可选 WebMCP

参照 search-current.md 的最新官方试验状态。先完成可访问DOM、表单标签、错误信息、键盘操作和可靠服务端行为。确有Agent产品需求时，再检查目标浏览器版本和规范，添加带清晰输入Schema的工具。

只读规格查询与会改变业务状态的操作分开。提交询盘、索样、上传图纸、创建CRM机会必须遵循现有授权和用户确认边界；不能用 toolautosubmit 来跳过商业判断。日志记录实际动作/结果，不记录密钥和无关个人资料。未在真实客户端执行成功的功能记 NOT_RUN，不因属性存在就评为 ADVANCED。
