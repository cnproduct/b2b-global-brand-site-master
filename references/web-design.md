# 网页设计、排版与视觉验收

本层将 `renwork-web-design-master` 的设计、跨语言排版和操作验收能力接入建站流水线。页面目标与事实边界沿用 [页面蓝图](site-blueprints.md) 和 [知识资产契约](knowledge-assets.md)；这里规定如何呈现和验证，不再建立第二套事实库、token 或评分规则。

## 先决定采购任务，再决定页面形态

每页实现前用一小段记录：主要买家、要完成的动作、信息顺序、可用品牌素材、字体角色及一个视觉重点。已有品牌优先继承。Logo 的颜色可以用于品牌和按钮；小字号文字、输入框边界与焦点使用独立的可读语义色，不把浅色 Logo 色直接套给所有文字。

模板采用编辑式 B2B 页面：首屏说明真实供应范围并提供下一步；参数、条件和文件可直接阅读；用对齐、留白和分隔线组织内容。真实媒体齐备时使用双栏首屏，缺少媒体时使用采购指引侧栏。不要用随机图库、虚构产能、空证书徽章或重复大数字填满首屏。

| `data-layout` | 当前 CSS 的实际差异 | 页面内容要配合的采购任务 |
|---|---|---|
| `engineering` | 文字稍宽的首屏；事实标题/值双栏；参数以表格与数字对齐 | 工况、型号、参数条件、资料与技术询问 |
| `materials` | 有媒体时媒体更宽；无媒体时文字更宽；5:4完整图片区域；两列材料入口 | 材质、表面、空间与安装关系；拉丁标题可使用获准的系统衬线字体 |
| `oem` | 品牌色需求侧栏；定制步骤按左侧线分组；合作入口具有明确块面 | 客户提供什么、能定制什么、样品确认和下一步 |
| `evidence` | 收敛标题字阶；正文控制行长；适用条件显著分组；资料入口按行排列 | 用途与适用范围、参数依据、文件版本、市场条件 |

四种版式使用相同的 DOM 阅读顺序和组件。窄屏按内容顺序归为单列，保留有效导航与主要行动；不隐藏关键采购内容或调整 CSS `order` 改变键盘阅读顺序。

## 共享 token 与组件

`tokens.css` 提供颜色、字体和尺寸；`templates/assets/css/b2b-industrial-core.css` 消费它们并提供合理 fallback。沿用 `--brand-*`、`--text-*`、`--font-*`，增加的语义角色为 `--focus-color`、`--control-border`、`--space-1..4`、`--section-space`、`--content-width`、`--reading-width`。项目需要其他框架时映射现有角色，不复制一套平行主题。

- `.hero` 包含 `.hero-copy` 与 `.hero-media` 或 `.hero-aside`；图片默认完整显示，避免裁掉产品结构。首屏媒体不延迟加载，真实尺寸由 HTML 记录；示意图保留可见说明。
- `.actions` 包含主 `.button` 与次 `.button.secondary`；链接执行跳转，按钮执行动作。标签写具体下一步，允许长文案换行。
- `.section-head` 建立区块标题与说明；`.link-grid > .link-card` 组织可点击的产品、应用或资料入口；`.section-nav` 指向真实区块锚点。
- 事实、规格、文件和询盘使用原生 `article`、`table`、`a`、`form`。表格放在有名称、可聚焦的 `.table-scroll` 中，窄屏可局部横向阅读。
- `.inquiry-panel` 使用 `.field`、`.field-error`、`.form-status`；HTML 必须将持久标签和错误信息关联到控件。`aria-invalid` 表示错误；状态元素通过文本与语义说明进度，不能仅换颜色。提交中保留输入并防重复，失败允许恢复；成功提示由真实服务响应驱动，收件另验。

表单 HTML 的 `hidden` 属性继续生效；不以占位文字代替标签，不使用全局 `overflow-x:hidden` 掩盖布局问题。长链接、型号、邮件地址和中文标题自然换行，Grid/Flex 子项允许收缩。常用独立按钮和导航使用至少 2.75rem 的触达高度；行内链接无需强行扩大成按钮。

## 跨语言与缩放

字号继承用户根字号，标题和区块使用含 `rem` 的流式字阶；不固定根字号或仅以 `vw` 表示字号。字阶是内容角色，不声称所有字号遵循同一数学比例。字体来自现有品牌和可用字形，缺少字体文件时使用系统 fallback，不因为 CSS 写了字体名就称其已加载。

拉丁正文从 `65ch` 阅读宽度开始；中文、日文、韩文按实际字形采用约 `36em` 的正文上限和更松的行高。`ch` 不是精确字符数，也不是汉字数。中日韩标题取消拉丁标题的紧字距，不强制大写；中文保留正常断行，长 URL/标识符才在必要时打断。繁体、日文、韩文使用对应字体 fallback，不强行套简体字形。

200% 页面缩放、用户文字放大和窄屏重排是不同检查；CSS 中存在 `clamp()` 不能替代实测。不要硬编码标题换行、固定文本容器高度或截断必读内容。若目标市场包含阿拉伯文/希伯来文，提供正确 `lang/dir` 并实测混合方向，逻辑属性仅是支持基础。

## 验收与记录

优先使用本项目已有工具。视觉修改不需要新测试框架；至少以一个实际公司内容页面和一份长文本/中文压力页面检查共享样式。先核实服务可达，再判断空白页或请求失败。按真实结果记录 PASS / FAIL / NOT_RUN，不汇总虚构设计分数。

| 检查 | 操作与可核对结果 |
|---|---|
| 版式和重排 | 320、390、768、1440 CSS px；四种版式各看一个实际页面；检查断点两侧、导航、长标题、长 URL 和空媒体 fallback |
| 放大与文本间距 | 200% 页面缩放后控件/提示不丢失；320 CSS px 下正文无非必要横向滚动；适用时测试行高 1.5、段距 2em、字距 .12em、词距 .16em |
| 交互与焦点 | 仅键盘完成跳过导航、区块跳转、文件打开、表单提交/错误恢复；焦点清楚且不被裁切；加载/错误/成功文本均可感知 |
| 实际对比度 | 普通文字 ≥4.5:1，大文字 ≥3:1；必要控件边界/状态图形按适用规则 ≥3:1。不能把 4.499 四舍五入判合格；图片/透明背景须测合成结果 |
| 触达 | 常用按钮采用约 44px 或更大设计目标；WCAG 2.2 AA 24×24 CSS px 及其间距/例外规则须单独判断，不混写成“AA 一律要求 44px” |
| 媒体与语言 | 正确 alt、真实图片尺寸、首屏/非首屏加载策略；真实中文/目标语言、字体失败后的替代字形；材料图不得误裁产品结构 |
| 状态与动效 | 实际存在的禁用、加载、错误和成功状态；减少动态效果设置下无需动画也能操作；未承诺暗色模式时不临时增加 |
| 功能与外部结果 | 本地静态检查、浏览器操作、后端接收、邮箱送达、部署、收录分别记录；截图正常不能替代询盘送达 |

简要记录：路由/提交 → 浏览器与视口/状态 → 观察和证据 → 发现与修复 → 未测项。没有实际浏览器验证时明确写“未做浏览器视觉验收”；颜色计算只证明被测色对，不证明整站 WCAG 合规。
