# 行业选择与交付规则

## 配置的作用

`assets/industries.json` 是采购内容与交互蓝图，不是经过所有行业真实转化测试的成品主题。字段、CTA、版式和主题词是设计建议，均不能证明目标企业拥有相应能力。标准与法规需结合具体 SKU、用途和目的国重新核验。

先识别主营产品 → 采购决策方式 → 业务身份 → 目标买家 → 目标市场。选主行业，不根据 Logo 颜色猜行业。跨行业企业可组合，但不同产品的参数与证据不可交叉继承。

## 每项配置如何使用

- `buyers` → 首页角色入口、应用页及询盘的语境。
- `decision_path` → 信息呈现顺序，不照搬统一 Hero + 三卡片。
- `product_fields` → 产品卡及横向比较；未知值留空并隐藏该事实，不能填行业常见值。
- `evidence` → 素材索取清单、质量页、下载中心；没有材料不生成假下载按钮。
- `homepage_sections` / `visual_direction` → 页面骨架和图像叙事；品牌 Logo 与用户偏好优先。
- `rfq_fields` → 行业补充字段，不要求访客填完所有信息；第一步保持短表单，技术字段渐进展开。
- `topic_clusters` → 研究种子，不代表搜索量、关键词难度或排名机会已验证。
- `red_lines` → 当前行业最易误写的公司事实。
- `missing_data_fallback` → 缺少事实时仍可交付的有用页面。

## 行业研究的小闭环

选定公司后搜索其正式名称、原有域名、主营类目及目标市场。优先公司资料与一手文件，再研究 3–5 个同类站点的选型、规格、证据和 RFQ 结构。记录 URL、检索日期、观察和适用边界；参考对方采购体验，不复制对方资质、型号、文案和照片。建议可以由观察推导，但标注为设计判断。

## 三种资料成熟度

**M0：Logo + 简介。** 建立品牌方向、行业地图、公司简介草稿、分类页、买家指南、资料清单、RFQ 草稿和本地网站。无型号时不捏造 SKU；无收件地址时不伪装表单成功。完整的是信息架构与工作方法，企业事实仍可不完整。

**M1：产品册 + 实拍 + 商务口径。** 增加真实产品页、参数对比、下载目录、OEM/ODM 流程、质量页面与可测试 RFQ。按已授权范围公开。

**M2：检测文件 + 真实案例 + 运营数据。** 扩展技术中心、证据化案例、应用页面、本地化市场内容和搜索实验。未获得客户授权的项目采用获准的匿名描述，仍须有内部证据。

## 行业扩展

超出以上行业时，在当前项目的 `industry.json` 中填充同样的字段。先研究该行业的采购决策和产品数据，再写模板。不要让一个过宽的“通用行业”掩盖医疗、食品、化学品等不同的证据要求。不要自动回写全局 Skill；只有用户要求维护它时再更新。
