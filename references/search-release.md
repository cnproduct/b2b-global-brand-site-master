# SEO、GEO、转化及上线验收

核验基线：2026-09-27；最新平台变化及来源优先参见 search-current.md，再看 research.md / sources.json。官方规则、平台接口和 Schema 支持会变化，每次项目执行时复查相关官方文档。

## SEO 的可执行工作

1. 建立搜索意图 → 页面 → 买家下一步矩阵。关键词包括产品/应用/材料/参数/工艺/问题/采购流程，目标国家与语言是研究条件。没有工具数据不得编搜索量和难度。
2. 每个公开页面有独立价值与可访问 URL；HTML 标题、H1、description、正文、图片替代文本及内部链接表达同一主题。不要塞关键词或机械替换同义词。
3. 核对 HTTP 状态、HTTPS、redirect/canonical、一致的主域和路径、robots、noindex、sitemap 及重要资源可获取性。保留可工作的 `.html` URL；只有实际迁移收益才改，并建立单跳重定向。
4. sitemap 只列可索引规范页面；lastmod 反映实质变更，不随每次构建刷新全部日期。不存在的分类/产品不进入 sitemap。
5. JSON-LD 与可见内容相同。Organization / WebSite / BreadcrumbList 按需使用；Product、Article/TechArticle 只用于对应页面。无真实报价/评价时不造 Offer/AggregateRating 来通过富结果测试。合法 Schema 与符合某类富结果资格是两件事。
6. sameAs 只链接同一公司实际拥有且已核实的档案，不伪造 Wikipedia/Wikidata/Crunchbase 页面。没有这些档案不妨碍建站。
7. 真多语言采用独立 URL、自指 canonical、对应页面互返 hreflang，合理设置 x-default；不能所有语言 canonical 到英文，也不要靠浏览器语言强制跳转。未翻译的页面不生成伪语言变体。
8. 模板筛选页、国家/城市页与批量 AI 文都须先证明独立用户价值；不能通过换地名/关键词制造 doorway 或规模化低价值内容。站群须有独立产品/受众/内容理由。

## GEO：可引用性与实测

Google 的 AI 功能仍以核心搜索原则为基础。2026 官方 AI 优化指南明确：`llms.txt` 不影响 Google 搜索可见性或排名；不需要把正文切成供 AI 使用的固定块，不需要专用 AI Schema。关注原创产品/工程信息、清晰事实、条件、图片、对比表和相关链接。

`llms.txt` 是可选的 Agent 导航提案。需要时生成简洁目录，链接实际公开 Markdown/HTML；与网页同一内容源，不能变成另一个夸大版本。2026-08 的 v2 提案支持路径范围和发现链接，没有通用 5000 词要求。是否维护 llms-full.txt 由消费者需求决定。

把以下四项分开：传统抓取/索引、搜索/检索机器人、模型训练机器人、用户发起的浏览访问。按照目标平台现行官方文档及站主意愿配置，不一律放行“所有 AI 机器人”。OpenAI 的 OAI-SearchBot 与 GPTBot 用途不同；robots 不能保护内部文件。

Google 于 2026-05-07 停止展示 FAQ rich results，6 月移除相应文档。保留有用 FAQ 内容，FAQPage 仅在有实际消费者需求及正确语义时使用，不作为 SEO 必得分项。WebMCP 和机器操作接口只在真实业务、环境支持和授权需求下添加，不设为内容站前置条件，表单不能自动寄样或承诺合同。

每家公司建立固定的品牌/非品牌/选型/比较问题集，例如 12–20 个实际采购问题。记录 engine、界面/模型、日期、国家/语言、问题、是否启用联网、答案/证据、引用 URL、是否误述、重复次数。覆盖竞品时只比较同一条件；人工小样本属于观察，不代表全部用户。

GEO 指标区分：提及率、带链接引用率、被引页面数、引用准确率、AI referral 会话、有效询盘、样品/报价进展。记录分母与观察窗口；不要把一次回答或 100 分审计当成增长证明。Bing AI Performance 可观察其支持的 Microsoft AI 场景，不能外推为全平台统计。Google 新版帮助页已提供 Generative AI performance report，主要展示 AI Overviews / AI Mode 的曝光，可按页面、国家、日期、设备查看。旧 AI-features 文档仍描述 Web 汇总口径，应优先采用新报告帮助页并检查账号实际可见性；不可把曝光当成点击/引用准确性或成交数据。

Google 生成式 AI 控制另检查目标属性的 Include/Exclude 有效值及继承来源；它与训练及普通索引分开。Bing 2026-06 的 Intents/Topics/Citation Share/Compare 按账号实际字段使用，引用份额不是流量份额。

## 发布质量表

| Gate | 检查 | 证据 |
|---|---|---|
| A 身份事实 | 公司/域名/角色、卡来源、失效和敏感信息、旧模板残留 | 内容抽查、claim 与资产映射 |
| B 设计访问 | 360/390/768/1440 常见宽度、键盘、焦点、表单标签、对比、减弱动画 | 截图和操作记录 |
| C 功能 | 内链/锚点、筛选比较、真实下载、询盘错误与重复提交、上传权限 | 自动/手动用例及结果 |
| D 搜索技术 | status、canonical、robots/noindex、sitemap XML、Schema 与内容 | 本地与公开 URL 分别检查 |
| E 性能 | 页面负载与 LCP/CLS，真实用户 INP；区分实验室和现场数据 | 测量工具、时间、设备/网络 |
| F 发布 | 构建、备份、目标域名、DNS、TLS、缓存、回滚 | 发布版本及线上检查 |
| G 询盘交付 | 目标收件/CRM 正确，获准测试的回执与记录 | 前端成功、服务端接受、最终收件分列 |
| H 可发现性 | GSC 所有权/sitemap/URL Inspection、Bing、可选 IndexNow | 各平台真实状态；未做记 NOT_RUN |
| I 业务结果 | 自然流量、查询、引用、有效询盘、报价、样品、成交 | 数据源和观察区间 |

WCAG 2.2 AA 为工程目标，不因自动扫描通过就宣称完全符合。当前 Core Web Vitals good 门槛为 p75 的 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，移动/桌面区分；Lighthouse 分数不能代替现场数据。

公网页面 200 不能证明渲染正确；前端成功不能证明邮箱收到；sitemap 提交不能证明抓取；请求收录不能证明已索引；已索引不能证明 AI 引用或询盘。待平台处理时保留状态与复查办法，不能无限重试或假装完成。

## 维护节奏（建议，不自动建立定时任务）

上线后先核验技术/询盘，随后按实际流量设 30/60/90 天观察窗口：补齐有需求的规格和问答、分析查询到页面匹配、检查主要国家与设备转化、修复事实过期。低流量时优先买家访谈和真实询盘分析，不做无统计意义的 A/B 胜负结论。用户要求定期监控时另创建其授权的自动化。
